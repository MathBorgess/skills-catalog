# Task-specific resources

Require a resource only when the chosen task needs the capability it provides. Check that the actual capability is usable in this session; an instruction file, package name, or launcher alone does not prove rendering, editing, or inspection works.

| Task need | Resource to check |
| --- | --- |
| Any web interface design direction and supported design checks | Impeccable (required for web work) |
| A selected interaction needs specialized motion guidance | Transitions.dev recipes, for that interaction |
| A required image needs generation or editing | An available image generation or editing tool; photos, thumbnails, and carousel imagery must be actually edited or generated when the brief requires it |
| Inspecting a rendered web interface | A usable browser or equivalent renderer and inspection capability |
| Exporting static pieces | The project's renderer or another usable graphics/export capability |

For web work, call the Skill tool with `impeccable` and use the relevant design playbook and supported checks. If the Skill tool is absent, read the installed Impeccable entrypoint and verify any required executable or integration before relying on it. Impeccable instructions and playbooks guide choices; they do not establish that a design was implemented or rendered. Follow the write guard in [briefing and design authority](briefing-and-design.md) for any operation that can change `DESIGN.md`.

Use the specialized motion recipes from Transitions.dev only when the selected interaction needs them. Use available image generation or editing tools only when the brief needs image creation or changes. For any named skill or provider resource, verify that the actual capability is usable; the name or readable instructions alone are not execution evidence. Use external references as sources; do not copy or vendor provider instructions or recipe collections.

If a necessary resource is unavailable, explain the specific capability and why this task needs it, then offer installation only when it can actually be carried out in this environment. Wait for the user's choice before installing. Verify the capability after authorized installation. If the user declines, installation fails, or the capability cannot be verified, stop the dependent work, explain what is blocked, and preserve the brief, decisions, and previews already produced. Do not replace required image editing with descriptions or placeholders.
