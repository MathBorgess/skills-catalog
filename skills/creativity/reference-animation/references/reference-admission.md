# Adding a design base

Keep one compositing workflow. Add a profile and a registry entry, not a new brand-specific skill.

For a reusable profile, record `id`, relative `profile`, `evidence_level` and `sources` (each with an inspectable URL and revision). Use `documented-practice`, `observed-example` or `measured-result`; a measured result also needs the measurement, population, conditions and limitations in the profile. Successful practice is not a promise of this work's performance.

Read the actual source. Extract its mechanism, applicable media, incompatible cases and the way it can bend toward the author's choices. Keep attribution. Do not copy executable instructions from an external SKILL.md into this workflow. Do not install its tools as a side effect of loading it.

Load the profile into context before composition. For a one-off source, use `--registry <json-file>` with the same schema; keep the JSON and profile together. The run snapshots the selected profiles, registry entries and hashes. Do not modify the installed skill just to use a one-off reference. New profiles must coexist with the original-wins policy and existing output format.
